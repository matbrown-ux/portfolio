<Chapter title="Overview" asideLabel="Services" aside={frontmatter.services}>

The Booking Flow is my own software for contractors and service businesses: roofers, HVAC and electrical crews, plumbers and general contractors. A business puts its lead form on its website, and from there the product does the work a busy owner never gets to. It replies to the lead the moment they ask, lets them book an estimate on the business's own calendar, sends the confirmation emails, follows up when they go quiet and keeps every lead in one dashboard.

I own all of it. I designed the brand and the interface, wrote the code, set up the billing and the email, and I run it now that it is live.

<PullQuote text="I designed it, built it, and I run it." />

</Chapter>

<Chapter title="The challenge">

A lead who fills out a form at 9:47 PM usually hears nothing until the next morning, and by then they have often called someone else. Owners of trades businesses are on a roof or under a sink all day, so the reply, the scheduling and the follow-up are the jobs that slip.

The product had to cover all of that without asking anything technical of the owner. It also handles other people's customers, calendars and payments, so I built it the way I would expect an enterprise product to be built, with tests and security checks on every change.

</Chapter>

What the product does after the form:

- **Replies at once.** The lead gets an email in the business's name with a link to book, and the owner gets an alert by email, with Slack, Microsoft Teams or Discord if they use one.
- **Follows up on its own.** Three follow-up emails over seven days stop as soon as the lead books. A reminder goes out the day before, a "We missed you" email after a no-show, and one Google review request after the job is marked done.
- **Tags where each lead came from.** Owners can label leads by source, such as their website, Angi, Thumbtack or Google Local Services Ads, and see which ones turn into booked jobs.
- **Bills and manages accounts.** Stripe runs a 14-day free trial, the plans and the billing portal, and owners on the Pro plan can invite their team.

<Chapter title="How I built it">

With no customers yet, the way the software is built is the best proof of what I can do. I hold this product to the same rules I would hold an enterprise team to.

**Test-driven development.** Every change to the code starts with a test that fails, and git hooks refuse a commit that changes code without one. The suite has 819 tests in 104 files, and it runs before every commit and again on GitHub. The database rules are tested too, against a real Postgres engine running inside the test suite.

**A security kit built on OWASP guidance.** I built my own security kit and installed it in this product. It follows the OWASP Top 10 and the OWASP Application Security Verification Standard, plus NIST's guidance on sign-in limits and the OWASP cheat sheets for input validation, injection, cross-site scripting and access control. In practice that means:

- Every endpoint goes through one shared wrapper that checks the request against a strict schema, with a length limit on every field, and applies a rate limit.
- Every webhook proves where it came from: Stripe's signature, or a shared secret compared in constant time.
- Every database table has row level security, and an access control matrix lists who can do what to each endpoint and table, deny by default, each row tied to the test that proves it.
- Secrets stay on the server. The kit blocks a key from reaching browser code, scans every commit and the git history for leaked secrets with Gitleaks and TruffleHog, scans the built site before it ships, and keeps a log of when each key was last rotated.
- Dependencies are audited on every push, and Semgrep scans the code against its OWASP Top 10 rules.
- Security headers come from one policy file, and a weekly job checks the live headers and the key rotation dates, then opens an issue when something is overdue.

These checks run on every commit and again on GitHub, so a change has to pass them before it reaches the live site.
