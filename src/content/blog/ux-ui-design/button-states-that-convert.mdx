## Why button states matter

Most buttons have five states: default, hover, focus, active and disabled. Most implementations only style two of them.

That leaves keyboard users without a visible focus state, and it leaves out the small details that make an interface feel finished.

## The five states

<Terms>
<Term name="Default">

This is the button at rest. It should be clean and readable, with enough visual weight to show it can be clicked.

</Term>
<Term name="Hover">

This is the button responding to the cursor. Use one subtle change: a colour change, a slight lift with `translateY(-2px)`, or a shadow. Don't use all three at once.

</Term>
<Term name="Focus">

This state matters most for keyboard navigation and accessibility. Use a visible `outline` or ring that passes WCAG 4.5:1 contrast against the background. Never set `outline: none` without a replacement.

</Term>
<Term name="Active">

This is the button being pressed. A slight compress with `scale(0.98)` tells the user the press registered.

</Term>
<Term name="Disabled">

This is the button that can't be clicked. Reduce opacity to 40 to 50%, change the cursor to `not-allowed`, and remove all hover effects.

</Term>
</Terms>

## Implementation

Here are all five states on one button, written with this site's colour tokens.

```tsx
<button
  className="px-6 py-3 bg-vermilion text-ink
    hover:bg-ink hover:text-ivory
    focus-visible:outline-2 focus-visible:outline-offset-2 focus-visible:outline-ink
    active:scale-[0.98]
    disabled:opacity-40 disabled:cursor-not-allowed
    transition-colors duration-200"
>
  Click me
</button>
```

Each state tells the user something specific, so design all five together as one system.
