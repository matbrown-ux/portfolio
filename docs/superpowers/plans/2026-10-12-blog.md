# Blog (Astro rebuild) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build the blog: an index at `/blog`, nine topic pages and the article template, from the MDX already in `src/content/blog/`.

**Architecture:** Two content collections (`blogTopics`, `blogArticles`) over one folder tree; an article belongs to the folder it sits in. All grouping, counting, sorting and labelling lives in tested `src/lib` modules, and static `.astro` components only render what those return. The single script is a small contents-list marker started from `BaseLayout.astro`.

**Tech Stack:** Astro 7 (static), MDX through `@astrojs/markdown-satteri`, Tailwind CSS v4, GSAP reveals through `data-reveal`, Vitest 5 with jsdom.

**Spec:** `docs/superpowers/specs/2026-10-12-blog-design.md`. Visual reference: `docs/superpowers/specs/assets/2026-10-12-blog-approved.jpeg` (sections B1 to B4, P1 to P3, R1 to R3). Read both before starting a task.

## Global Constraints

- Branch `feat/astro-rebuild`. Do not merge to `main`, push or deploy.
- Test-first for every source file (`.ts` under `src/`): write the test, watch it fail, then implement. Never use the git skip-verification flag, never add a `Test-Exempt:` trailer.
- `.astro`, `.mdx`, `.css`, `*.config.*` and files in `public/` are content and need no unit test, but nothing with a branch or a calculation may live in `.astro` frontmatter.
- No em dashes or en dashes in any visible copy, MDX, alt text or frontmatter. Straight quotes, no emojis, sentence case in the markup.
- First person copy ("I", "my"). No "we". Use the strings in this plan and the spec exactly; do not invent copy, metrics or claims.
- Colours come only from the tokens `ivory`, `ink`, `vermilion`, `stone`, `line-dark` (opacity modifiers such as `border-ink/15` are fine). Small vermilion text only on ink; text on a vermilion fill is ink. Square corners everywhere.
- Type utilities: `type-display` (Anton) and `type-label` (JetBrains Mono). Body text is Archivo.
- Hover and focus effects must not move an ink surface with `transform`. Change colour, or move a small glyph inside.
- Reveals are declared with `data-reveal` (`rise`, `wipe`, `fade`), `data-reveal-on="load"` and `data-reveal-delay`; nothing else animates. No new durations or eases.
- At most two handwritten `ScriptArt` moments a page: the index has `notes` and the contact band; topic and article pages have only the contact band.
- A "topic" is what old files call a pillar. Visitors only see "topic".
- Hrefs have no trailing slash (`/blog/ux-ui-design`), like the existing `/work/<slug>` links.
- Commit after each task with this trailer, written in one heredoc with no blank line between the two lines:
  ```

  Claude-Session: <the current session URL>
  ```
- Never stage `.codex/`, `AGENTS.md`, `.fonts/`, `.superpowers/` or `.playwright-mcp/`.
- Browser checks run against your own `npx astro dev --port 4321`; stop it with `npx astro dev stop`. Never kill servers by name. Sizes given in the component code are starting points: tune them in the browser against the reference image.

## Settled before the plan (the spec lists these as risks)

- **Code colouring works.** `@astrojs/markdown-satteri` 0.4.3 passes `markdown.shikiConfig` to Shiki, and `theme: 'css-variables'` emits `--astro-code-*` variables, so the palette is set in CSS. Every `<pre>` gets `class="astro-code"` and `data-language`.
- **Contents headings come from `render()`.** The processor records `{ depth, slug, text }` for every heading and adds the matching `id`.
- **One change from the spec:** the spec asks for a unit test that the `noindex` rule and the sitemap rule agree on the real content folder. A unit test cannot call `getCollection`, so the agreement is checked on the built site in Task 9 instead.

## Review Focus

1. **An article file in a folder with no `index.mdx`.** A person would expect the build to stop and name the folder, not a page with `undefined` in it. Pinned in Task 3 (`requireTopic`).
2. **A discipline with no proof case study, or one whose case study was removed.** The empty topic panel must drop the case study clause rather than print "the undefined case study". Pinned in Task 3 (`emptyTopicText`).
3. **Two articles published on the same date.** Their order must be the same on every build and on every page. Pinned in Task 3 (`sortArticles`).
4. **An article with no `h2`, or only one.** The contents list must not render as an empty box or a one-item list. Pinned in Task 3 (`contentsHeadings`).
5. **A date near midnight on a build machine in another time zone.** "31 May 2026" must not become "30 May 2026". Pinned in Task 3 (`formatDate`, `isoDate`).

Also exercised in tests: an empty or whitespace-only body (Task 2, reading time), and a contents link whose heading is missing from the page (Task 7).

## Suggested model per task

Tasks 1, 2, 3 and 7 carry complete code: the cheapest model. Tasks 8 and 9 (copy, docs and build checks): the mid model. Tasks 4, 5 and 6 are judged in the browser: the strongest model. Every per-task review: the mid model. The final whole-branch review: the strongest model.

`src/lib/readingTime.ts`
```ts
/** Words read in a minute. */
const WORDS_PER_MINUTE = 200

/** Minutes to read an article's raw MDX body, rounded up and never less than one. */
export function readingMinutes(body: string): number {
  const words = body.split(/\s+/).filter(Boolean).length
  return Math.max(1, Math.ceil(words / WORDS_PER_MINUTE))
}

/** The reading time as shown beside an article's date, for example "2 min read". */
export function readingLabel(body: string): string {
  return `${readingMinutes(body)} min read`
}
```

`src/lib/emptyTopics.ts`
```ts
import { readdirSync } from 'node:fs'
import { join } from 'node:path'

/**
 * The topic folders under the blog content folder that hold no article: no .mdx file other than
 * index.mdx. Their pages are left out of the sitemap and carry noindex until they have one.
 */
export function emptyTopicSlugs(blogDir: string): string[] {
  return readdirSync(blogDir, { withFileTypes: true })
    .filter((item) => item.isDirectory())
    .filter((item) => !readdirSync(join(blogDir, item.name)).some((file) => file.endsWith('.mdx') && file !== 'index.mdx'))
    .map((item) => item.name)
    .sort()
}

/** Whether a sitemap URL is the page of one of the given empty topics. */
export function isEmptyTopicUrl(page: string, slugs: string[]): boolean {
  const path = new URL(page).pathname.replace(/\/$/, '')
  return slugs.some((slug) => path === `/blog/${slug}`)
}
```

import type { Discipline } from '../content/disciplines'
import { readingLabel } from './readingTime'

/** The part of a blog topic entry these helpers need. The id is the topic's folder name. */
export interface TopicEntry {
  id: string
  data: { title: string; description: string; discipline: string; order: number }
}

/** The part of a blog article entry these helpers need. The id is "<topic>/<article>". */
export interface ArticleEntry {
  id: string
  /** The raw MDX, without frontmatter. */
  body?: string
  data: { title: string; description: string; date: Date }
}

export function topicSlug(articleId: string): string {
  return articleId.split('/')[0]
}

export function articleSlug(articleId: string): string {
  return articleId.split('/').slice(1).join('/')
}

export function topicHref(topicId: string): string {
  return `/blog/${topicId}`
}

export function articleHref(articleId: string): string {
  return `/blog/${articleId}`
}

/** Newest first, with the id as a stable tiebreak. Does not reorder the input. */
export function sortArticles<T extends ArticleEntry>(articles: T[]): T[] {
  return [...articles].sort((a, b) => b.data.date.getTime() - a.data.date.getTime() || a.id.localeCompare(b.id))
}

/** A topic's articles, newest first. */
export function articlesInTopic<T extends ArticleEntry>(articles: T[], topicId: string): T[] {
  return sortArticles(articles.filter((article) => topicSlug(article.id) === topicId))
}

/** The newest `n` articles across every topic. */
export function latestArticles<T extends ArticleEntry>(articles: T[], n: number): T[] {
  return sortArticles(articles).slice(0, n)
}

/** The topic with this id. An article in a folder with no index.mdx stops the build here. */
export function requireTopic<T extends TopicEntry>(topics: T[], id: string): T {
  const topic = topics.find((entry) => entry.id === id)
  if (!topic) throw new Error(`src/content/blog/${id} has no index.mdx, so its articles have no topic`)
  return topic
}

export function requireDiscipline(disciplines: Discipline[], slug: string): Discipline {
  const discipline = disciplines.find((entry) => entry.slug === slug)
  if (!discipline) throw new Error(`Unknown discipline "${slug}"`)
  return discipline
}

const NUMBER_WORDS = ['zero', 'one', 'two', 'three', 'four', 'five', 'six', 'seven', 'eight', 'nine', 'ten', 'eleven', 'twelve']

/** A count as a word up to twelve and as digits above, for use inside a sentence. */
export function numberWord(n: number, capital = false): string {
  const word = NUMBER_WORDS[n] ?? String(n)
  return capital ? word.charAt(0).toUpperCase() + word.slice(1) : word
}

/** "1 article", "3 articles"; with `words`, "nine topics". */
export function countLabel(n: number, singular: string, plural: string, options: { words?: boolean; capital?: boolean } = {}): string {
  const count = options.words ? numberWord(n, options.capital) : String(n)
  return `${count} ${n === 1 ? singular : plural}`
}

export interface TopicRow<T> {
  topic: T
  href: string
  count: number
  /** "2 articles", or "Nothing yet" for an empty topic. */
  status: string
}

export interface TopicGroup<T> {
  discipline: Discipline
  topics: TopicRow<T>[]
}

/** One group per discipline that has topics, in discipline order, each topic with its article count. */
export function topicGroups<T extends TopicEntry>(disciplines: Discipline[], topics: T[], articles: ArticleEntry[]): TopicGroup<T>[] {
  return disciplines
    .map((discipline) => ({
      discipline,
      topics: topics
        .filter((topic) => topic.data.discipline === discipline.slug)
        .sort((a, b) => a.data.order - b.data.order || a.id.localeCompare(b.id))
        .map((topic) => {
          const count = articlesInTopic(articles, topic.id).length
          return { topic, href: topicHref(topic.id), count, status: count > 0 ? countLabel(count, 'article', 'articles') : 'Nothing yet' }
        }),
    }))
    .filter((group) => group.topics.length > 0)
}

/** The other topics in the same discipline, by their order. */
export function siblingTopics<T extends TopicEntry>(topics: T[], topic: TopicEntry): T[] {
  return topics
    .filter((entry) => entry.data.discipline === topic.data.discipline && entry.id !== topic.id)
    .sort((a, b) => a.data.order - b.data.order || a.id.localeCompare(b.id))
}

export interface Crumb {
  label: string
  /** Left out for the current page. */
  href?: string
}

/** The trail above a topic or an article. On an article page the topic is a link and the article is not listed. */
export function breadcrumb(discipline: Discipline, topic: TopicEntry, page: 'topic' | 'article'): Crumb[] {
  return [
    { label: 'Blog', href: '/blog' },
    { label: discipline.title, href: `/blog#${discipline.slug}` },
    page === 'article' ? { label: topic.data.title, href: topicHref(topic.id) } : { label: topic.data.title },
  ]
}

const MONTHS = ['January', 'February', 'March', 'April', 'May', 'June', 'July', 'August', 'September', 'October', 'November', 'December']

/** "31 May 2026", read in UTC so the build machine's time zone cannot shift the day. */
export function formatDate(date: Date): string {
  return `${date.getUTCDate()} ${MONTHS[date.getUTCMonth()]} ${date.getUTCFullYear()}`
}

/** "2026-05-31", for a `<time datetime>`. */
export function isoDate(date: Date): string {
  return date.toISOString().slice(0, 10)
}

export interface Heading {
  depth: number
  slug: string
  text: string
}

/** The headings the contents list shows: second level only, and none unless there are at least two. */
export function contentsHeadings(headings: Heading[]): Heading[] {
  const sections = headings.filter((heading) => heading.depth === 2)
  return sections.length >= 2 ? sections : []
}

/** What an empty topic page says. The case study clause is dropped when the discipline has no proof. */
export function emptyTopicText(disciplineTitle: string, proofTitle: string | null): string {
  const service = `The ${disciplineTitle} service page explains how I work on it`
  const proof = proofTitle ? `, and the ${proofTitle} case study shows it on a real business.` : '.'
  return `I haven't written anything on this topic yet. ${service}${proof}`
}

/** What a list needs to show one article. */
export interface ArticleCard {
  href: string
  title: string
  description: string
  topicTitle: string
  dateLabel: string
  dateIso: string
  readLabel: string
}

export function articleCard(article: ArticleEntry, topicTitle: string): ArticleCard {
  return {
    href: articleHref(article.id),
    title: article.data.title,
    description: article.data.description,
    topicTitle,
    dateLabel: formatDate(article.data.date),
    dateIso: isoDate(article.data.date),
    readLabel: readingLabel(article.body ?? ''),
  }
}

export interface Tile {
  label: string
  title: string
  text: string
  cta: string
  href: string
}

/**
 * The three "where next" tiles under an article: more from its topic (the newest other article,
 * or the topic page when it is the only one), the service behind it, and the way back to the blog.
 */
export function nextTiles(input: {
  article: ArticleEntry
  articles: ArticleEntry[]
  topic: TopicEntry
  discipline: Discipline
  topicCount: number
  disciplineCount: number
}): [Tile, Tile, Tile] {
  const { article, articles, topic, discipline, topicCount, disciplineCount } = input
  const other = articlesInTopic(articles, topic.id).find((entry) => entry.id !== article.id)
  const more: Tile = other
    ? { label: 'More on this topic', title: other.data.title, text: other.data.description, cta: 'Read the article', href: articleHref(other.id) }
    : {
        label: 'More on this topic',
        title: topic.data.title,
        text: 'Other articles on this topic appear here as I publish them.',
        cta: 'See the topic',
        href: topicHref(topic.id),
      }
  return [
    more,
    { label: 'The service behind it', title: discipline.title, text: discipline.blurb, cta: 'See the service', href: `/services#${discipline.slug}` },
    {
      label: 'Keep reading',
      title: 'All articles',
      text: `${countLabel(topicCount, 'topic', 'topics', { words: true, capital: true })} across ${countLabel(disciplineCount, 'discipline', 'disciplines', { words: true })}.`,
      cta: 'Back to the blog',
      href: '/blog',
    },
  ]
}

## Why button states matter

Most buttons have five states: default, hover, focus, active and disabled. Most implementations only style two of them.

That leaves keyboard users without a visible focus state, and it leaves out the small details that make an interface feel finished.

## The five states

<Terms>
<Term name="Default">

This is the button at rest. It should be clean and readable, with enough visual weight to show it can be clicked.

</Term>
<Term name="Hover">

This is the button responding to the cursor. Use one subtle change: a colour change, a slight lift with `translateY(-2px)`, or a shadow. Don't use all three at once.

</Term>
<Term name="Focus">

This state matters most for keyboard navigation and accessibility. Use a visible `outline` or ring that passes WCAG 4.5:1 contrast against the background. Never set `outline: none` without a replacement.

</Term>
<Term name="Active">

This is the button being pressed. A slight compress with `scale(0.98)` tells the user the press registered.

</Term>
<Term name="Disabled">

This is the button that can't be clicked. Reduce opacity to 40 to 50%, change the cursor to `not-allowed`, and remove all hover effects.

</Term>
</Terms>

## Implementation

Here are all five states on one button, written with this site's colour tokens.

    focus-visible:outline-2 focus-visible:outline-offset-2 focus-visible:outline-ink
    active:scale-[0.98]
    disabled:opacity-40 disabled:cursor-not-allowed
    transition-colors duration-200"

  Click me
</button>

`src/lib/tocSpy.ts`
```ts
/** The top 30% of the viewport: a heading that has reached it counts as the section being read. */
const BAND = '0px 0px -70% 0px'

/**
 * Mark the section being read in an article's contents list. The list is `nav[data-toc]` and each
 * link points at a heading by id. The link for the last heading to reach the top band of the
 * viewport gets aria-current="location"; before any has, the first link has it. Without
 * IntersectionObserver the list stays as plain links. Returns a cleanup function.
 */
export function initTocSpy(root: ParentNode = document): () => void {
  const nav = root.querySelector('[data-toc]')
  if (!nav || typeof IntersectionObserver !== 'function') return () => {}

  const sections = Array.from(nav.querySelectorAll<HTMLAnchorElement>('a[href^="#"]')).flatMap((link) => {
    const heading = document.getElementById(decodeURIComponent(link.getAttribute('href')!.slice(1)))
    return heading ? [{ link, heading }] : []
  })
  if (sections.length === 0) return () => {}

  const reached = new Set<Element>()

  function mark() {
    let current = sections[0].link
    for (const { link, heading } of sections) if (reached.has(heading)) current = link
    for (const { link } of sections) {
      if (link === current) link.setAttribute('aria-current', 'location')
      else link.removeAttribute('aria-current')
    }
  }

  const observer = new IntersectionObserver(
    (entries) => {
      for (const entry of entries) {
        // Reached means at or above the band's bottom edge: inside the band, or scrolled off the top.
        const isReached = entry.rootBounds ? entry.boundingClientRect.top < entry.rootBounds.bottom : entry.isIntersecting
        if (isReached) reached.add(entry.target)
        else reached.delete(entry.target)
      }
      mark()
    },
    { rootMargin: BAND },
  )

  for (const { heading } of sections) observer.observe(heading)
  mark()

  return () => {
    observer.disconnect()
    for (const { link } of sections) link.removeAttribute('aria-current')
  }
}
```
